# 设计说明 · interceptive-ortho-management-index

这份文档回答一个问题：**为什么这个 skill 长成现在这样。**

它不是使用说明（那在 [`../README.md`](../README.md)），也不是题库或手册（那在 [`../reference/`](../reference/)）。它记录的是取舍：哪些做法被采用、哪些被否掉、代价是什么。

- 来源文章：《早矫，是利润的倍增器，还是定时炸弹？》
  <https://mp.weixin.qq.com/s/hA7245ZfcT8UHMKGUY-n4A>
- 原文未随仓库分发。仓库内对文章观点只做**短引（≤ 20 字）与转述**，不复制段落。

## 1. 为什么是"四个维度"，而不是照抄文章的六个动作

文章给的是六个可落地的动作（文章对应的小节名分别是"方案要审，结果要核""方案要拿出来反复看""每一次就诊，都如实记录""提成，按阶段发""财务的账，要算明白""把质控体系建立起来"）。本仓库把这六个动作编成 ACT-1 – ACT-6，并按本 skill 的分工重新命名：ACT-1 建标准、分级、看底数 / ACT-2 结果要核 / ACT-3 阶段目标要跟 / ACT-4 每次就诊都留痕 / ACT-5 提成按阶段发 / ACT-6 财务的账要算明白。直接把这六条变成六组题目，看起来最忠实，实际上会坏掉三件事：

1. **处方不能当体温计**。六个动作回答的是"该做什么"，而体检要先回答"你现在在哪"。用"你做了吗"当题干，答案天然是"做了 / 没做"的二元判断，出不了分档，也就排不出优先序。
2. **题量不均，分数不可比**。六个动作的覆盖面差别很大：有的动作牵涉 6 道题，有的只有 3 道。按动作直接计分，等于暗中给不同动作不同的权重，总分就没有解释力。
3. **处方会诱导答案**。"你们有没有做结束复核？"这种问法本身就在暗示"应该有"。而管理者对"该做什么"往往比对"现状是什么"更敏感，容易答出理想状态。

取而代之的是**四个维度**——它们描述的是**可测量的管理状态**，不是该做的事情：

| 维度 | 它测量的状态 | 一句话 |
|---|---|---|
| A 标准与分级 | 有没有标准、标准落在谁手上 | 有没有靶子 |
| B 方案审核与结案 | 有没有第二个人核、核得动不动 | 有没有人核 |
| C 记录与过程数据 | 看不看得见过程 | 看不看得见 |
| D 财务与激励 | 账明不明白、钱跟着什么走 | 账清不清楚 |

四个维度各 6 题、每题 0/1/2/3 分，维度内等权，维度分满分 18 → 折算成 0–100 才好读。这样每一题对总分的贡献是明确的，维度之间也能横向比较。

同时，六个动作并没有被丢掉：每个动作都挂着**它要解决的题号**（映射表在 [`../reference/playbook.md`](../reference/playbook.md) 各动作的标题里，优先序算法在 [`../SKILL.md`](../SKILL.md) 的「动作优先序」一节）。于是流程是"测量 → 定位缺口 → 翻译成文章原本的处方"，而不是"拿处方当尺子"。

**代价**：题目和动作不是一一对应的，读报告的人需要在"分数"和"该做什么"之间做一次翻译。这个翻译由 skill 自动完成，写进报告的"改进动作"一节。

## 2. 评分与定级为什么这样切

- **每题 0/1/2/3 四档，而不是"是 / 否"**。管理现状很少是非黑即白：从"完全靠印象"到"随时能查、还能按医生下钻"中间有很长的过渡带。四档锚点写的是**可观察的行为**（能不能查、要花多久、有没有留痕），不是态度。
- **先维度分，再总分**。总分取四个维度分的平均，而不是 24 题直接加总。这样任何一个维度塌陷都不会被其他维度的分数稀释掉——一家机构"账算得很清楚但没人核方案"，和"有标准但没账"，总分可能相近，维度画像却完全不同，报告要给的是画像。
- **等级是区间，不是排名**。L1–L4 描述的是管理成熟度阶段，用来决定"先做什么"。它不是行业排名，仓库里也没有任何行业常模可供比较（见第 6 节）。

## 3. 为什么设红线，而且是"降级封顶"

红线（R1–R4）是四个致命信号：

| 红线 | 判据 | 性质 |
|---|---|---|
| R1 | 在册病例底数说不清 | 看不见 |
| R2 | 没有量化周期标准，也不知道平均延期几个月 | 没有靶子 |
| R3 | 结束仅由经治医生口头判定，无书面复核 | 没人核 |
| R4 | 预收款在收款当月 / 次月一次性发全额提成 | 钱先走了 |

它们只用一个动作影响结论：**命中任意一条，等级封顶到 L2；命中两条及以上，封顶 L1。** 封顶只改等级、不改总分——总分栏永远显示原分，否则报告会把"画像"和"判断"混成一体。

之所以不是"扣分"，是因为扣分和封顶是两种不同的判断：

- **扣分是量的调整**——"你在这一项上比平均差一点"。它预设了其他项可以补偿：只要别的维度做得好，总分还能拉回来。
- **封顶是质的判断**——"这个状态让其他分数失去意义"。底数说不清的时候，问卷里那些"我们大概是这样"的答案全都无从核实；结束没有人核的时候，所有延期、质量、成本数据都建立在经治医生的自述上；钱在服务交付前发完的时候，后面所有管理动作都缺少动力来源。

换句话说，红线不是为了惩罚低分机构，而是**防止高分幻觉**。一个擅长填表的机构完全可能在这四条上全部踩线，而它的总分不该因此显得体面。

**代价**：封顶会掩盖维度画像的细节。所以报告要求在给出封顶结论的同时，仍然逐维度展示得分——封顶改变的是等级，不改变画像。

## 4. 为什么报告必须逐题回指用户原话

报告的每一条判断都要能回指到「**题号 + 用户原话的关键点**」。24 题必答，所以每题都有原话可回指——答"不知道"也是一条原话。这条纪律有三个用途：

1. **可反驳**。受访者看到"你说的是 X，我据此判了 0 分"，可以当场指出"我其实说的是 Y"。不可反驳的结论没有改进价值，只会引发争执。
2. **防脑补**。LLM 很容易顺着"早矫机构一般都会……"把答案补齐。回指原话是把模型的先验摁住的最简单机制：找不到原话就不能写结论。
3. **让"不知道"合法**。多数体检工具隐含地惩罚"答不出来"，于是受访者学会估一个数。这里反过来：不知道是可以的，按锚点判分（通常是 0 档）就行；但它必须是一条真实的回答，不能是空白。

配合它的是一条提问纪律：**一题一问**。一次抛出多题会诱发一次性概括，丢掉细节。开场可以说明"一共 24 题、大约 15–25 分钟"——那是预期管理；被禁止的是**预告题目的内容或方向**，那会让受访者按"整张问卷想要什么"来组织回答，而不是按实际情况回答。相应地，用户看不到"还剩几题"的实时进度条，只能看到总数。这是刻意换来的干净数据。

## 5. K1–K8：来源与"未知即结论"的取舍

八个关键指标不是新发明，它们是文章里被反复点名的那几个数：

| 指标 | 大致出处（文章中的说法） |
|---|---|
| K1 在册病例数 | "先把自家病例的底数摸清楚" |
| K2 超期病例占比 | 计划时长是判断延期的前提 |
| K3 计划 / 实际结束时长 | "计划结束时长是管理的第一步" |
| K4 平均延期月数 | 开篇那个"不一定有答案"的问题 |
| K5 计划外复诊率 | 托槽脱落、钢丝扎嘴这类隐性操作 |
| K6 就诊次数与椅位占用 | 文章点名要进报表的三个数中的两个 |
| K7 重启次数 / 重启率 | 同上三个数中的第三个 |
| K8 单例就诊次单价 | "没了这个数，也就无法横向和其他项目比较" |

设计上的关键取舍只有一条：**未知即结论**。

任何一个 K 值拿不到，报告不估算、不跳过，而是写"未知"并给出取证方式——**哪一种报表、哪一个字段能把它查出来**。理由有三个：

- **估算会污染度量本身**。这个 skill 卖的就是"可见度"。如果用推测值把空白填上，得到的恰好是一个看起来什么都测过的假象——问题会被平均数抹平。
- **未知指向一个具体动作**。"我们不知道平均延期几个月"这句话本身没有用；"去病例管理系统按'计划结束日期'与'结案日期'两个字段导一次"才是可执行的动作。所以未知必须与取证方式同时出现，否则不算完成。
- **未知是横向可比的前提**。机构之间口径不同，宁可留空也不统一到某个假定的口径上。

工具 `tools/early_ortho_metrics.py` 沿用同一纪律：列缺失、整列为空、单元格解析不出来，都打印 `未知（缺少字段: xxx，建议从 xxx 导出）`，**绝不猜数、不用 0 顶替**。它也只接受字段名可配置的脱敏 CSV，不假定任何一家机构的具体表结构。它自己能算的只有 K1、K2、K3、K4、K6、K7、K8 的部分口径；K5 需要记录里带"计划外处理标识"，工具不读，直接报未知。

## 6. 已知局限

承认局限比补充功能重要。请在使用结论前先读这一节。

1. **一切结论以受访者自述为依据**。分数、红线判定、K 值都来自访谈中的口头回答与一张自选的 CSV。受访者记错、口径不一致、或者有意美化，工具都无法识别。
2. **没有临床核查**。这不是病历质控，也不看片子、不看模型、不看咬合。一个机构可能管理很差但临床很好，也可能反过来。本 skill 只谈管理。
3. **无法验证数据真实性**。工具算的是"你给的这张 CSV 说了什么"，不是"事实是什么"。它不做交叉校验，也不会去核对挂号系统、收费系统与病例系统是否一致。
4. **24 题是有意收窄的覆盖面**。营销获客、人事、供应链、门店扩张等都没有覆盖。文章在因果链里只提到过其中的门店扩张，本 skill 没有能力评价它们。
5. **评分带主观性**。0/1/2/3 锚点写的是可观察行为，能压缩判断空间，但压缩不到零：同一次回答，两个人可能给出相邻的两档。所以报告重点看维度画像与红线，不要把总分当成小数点后精度的成绩。
6. **等级不是行业基准**。L1–L4 只在本 skill 内部有意义，仓库里没有行业常模或分位数。别拿它当排名，也别拿它对外宣传。
7. **改进建议不是处方**。[`../reference/playbook.md`](../reference/playbook.md) 给的是管理动作与其完成判据，涉及收入确认、提成制度、预收款与托管的部分属于法律与会计范畴，必须由本机构的专业人士确认后再执行。
8. **工具的口径固定，机构口径不固定**。月份按 365.25 / 12 = 30.4375 天折算，超期按"计划结束日早于统计截止日"判定。你的系统若用别的口径，两边对不上是正常的——对不上时以能说清口径的那一个为准。

## 7. 维护约定

- **编号是契约**：四维度、L1–L4、R1–R4、ACT-1–ACT-6、K1–K8 的编号与名称在仓库内唯一，改动要同步 `SKILL.md`、`reference/`、本文件与 README。
- **提问纪律以"一题一问"为默认**：一题一问、不预告题目内容或方向、不替受访者填答案。任何"为了效率"把多题合并的改动都是在拆掉第 4 节的地基。唯一的例外在 SKILL.md：用户明确坚持要一次拿到全部题目时，可以转入批量模式，但必须先说明诊断质量会下降，并在报告里标注"未逐题追问，证据强度较低"——例外要留痕，不能变成默认。
- **来源纪律**：不在仓库内复制文章长段；不引入文章之外的机构数据或行业断言；示例数据一律虚构。
- **数据边界**：仓库不得出现任何真实患者信息（姓名、手机号、身份证号）或机构内部文件名。
- **改动后必须复算样例**：`docs/example-run.md` 是自测样例，它不是装饰——改动评分规则、红线判据、动作覆盖题号后，都要重算它的维度分、总分、红线结论与优先序，并核对正文里的每一个数字。样例与规则不一致，等于规则没有被验证过。
