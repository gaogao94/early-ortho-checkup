# early-ortho-checkup · 早矫管理体检

> 一个让 AI 智能体执行的**诊断问卷 skill**：用**一题一问**的方式访谈早矫（儿童青少年早期矫治）机构负责人，量化判断这家机构"早矫做得好不好、管得住管不住"，再按命中的缺口给出可执行的改进动作。

它的立场一句话：**看得见，才管得住。**

早矫这门生意，管得好是利润的倍增器，管不好是定时炸弹。差别通常不在营销，而在三件事：有没有标准、有没有留痕、有没有一本明白的账。

- **主要用户**：门诊老板、门诊管理者（店长 / 医疗总监）、正畸学科负责人。
- **前置要求**：不需要懂统计，不需要先上系统。答不出来本身就是重要信息。
- **不做什么**：不诊断患者、不给临床建议、不做法律或会计意见。

## 一次运行会发生什么

| 环节 | 内容 |
|---|---|
| 访谈 | 4 个维度、24 道题（A1–A6 / B1–B6 / C1–C6 / D1–D6），**助手一次只问一个问题** |
| 时长 | 约 15–25 分钟，一题一答 |
| 评分 | 每题 0 / 1 / 2 / 3 分；维度分 = 该维度 6 题之和 ÷ 18 × 100；总分 = 四个维度分的平均（均四舍五入取整） |
| 定级 | L1 无标准 / L2 刚起步 / L3 有体系 / L4 能自转；**命中红线会降级封顶** |
| 产出 | 一份《早矫管理体检报告》：等级、红线诊断、逐题证据、改进动作、90 天路线图、K1–K8 指标表 |
| 呈现 | 同一份报告三种形态：**Markdown**（对话里直接读）、**shadcn 风格单页 HTML**（点开/转发/打印）、**PNG 图片**（发微信、贴 PPT） |

报告默认同时产出一页 HTML——它是给老板、合伙人、门店管理层看的东西，一页能点开、能转发的页面比一段聊天记录有用得多。三种形态内容一致，只是呈现方式不同。

访谈纪律（这也是它和"发一张问卷"的区别）：

- 一次只问一个问题；开场会说清"一共 24 题、大约 15–25 分钟"，但**不预告后面的题目内容或方向**，避免诱导；
- **没有"跳过"这个选项**：答不上来就说"不知道"，那也是有效答案（通常按 0 档判分）；但**跳题就不出报告**——24 题缺一题都不行；
- 答得含糊就会被追问同一题（"这个数现在能查到吗？查一次要多久？"）；
- 助手不替你填空：你说"应该差不多"，它记的就是"说不清"；
- 能出示就出示：有现成的表或文件直接发过去，拿不出来就按低档判——助手不会替你抬高答案；
- 每答完一题落一条账：`题号 | 你的原话关键点 | 判分 | 依据`；
- 指标答不出来不扣人，但要如实记成"未知"，并写清这个数该从哪张报表取。

如果你明确坚持"一次把 24 题发给我"，可以转入批量模式，但要先知道代价：诊断质量会明显下降（少了对每题的追问），报告里会标注"未逐题追问，证据强度较低"。默认仍然是一题一问。

## 怎么用

### 场景 A：Claude Code / Agent Skills 用户

把仓库放进 skills 目录：

```bash
git clone https://github.com/gaogao94/early-ortho-checkup.git ~/.claude/skills/early-ortho-checkup
```

（已经下载过的话，直接把这个仓库目录拷进你的 skills 目录也可以。）然后用自然语言触发，例如：

- "给我做一次早矫管理体检"
- "用 early-ortho-checkup 看看我们门诊的早矫管理"

### 场景 B：任意能读文件的 AI 助手

把仓库里的 `SKILL.md` 与 `reference/` 目录一起交给它，然后说：

> 按 SKILL.md 对我做早矫体检。

`reference/question-bank.md` 是唯一的提问来源，`reference/playbook.md` 是唯一的建议来源——两份都给它，否则报告会缺题或缺动作。

### HTML 报告依赖

单页 HTML 由 [answer-me-with-html](https://github.com/QingYunA/answer-me-with-html) 的 `am` CLI 负责版式与组件渲染，本仓库只提供报告规范与数据转换，不重复造排版轮子。

```bash
git clone https://github.com/QingYunA/answer-me-with-html.git ~/.answer-me-with-html/am
export AM_CLI=~/.answer-me-with-html/am/skills/answer-me-with-html/scripts/am.mjs
python tools/render_report.py report.json --png --am "$AM_CLI"
```

只想要 Markdown 报告、不装 `am` 也能完整使用本 skill——HTML 只是多一种呈现。第一次跑 HTML 前用 `python tools/render_report.py --help` 看默认路径。

## 最短用法示例

下面是真实节奏的摘录（**机构与数字均为虚构，仅示意**）：

> **用户**：我们是××口腔门诊，3 名正畸医生，想做一次早矫管理的体检。
>
> **助手**：好。这是一次机构管理体检，大概 15–25 分钟，一共 24 个问题，我一次只问一个，你按实际情况答就行；查不到或者不确定，直接说"查不到"，这本身就是我要记录的信息。第一个问题：你们现在在册的早矫病例一共多少例？其中有多少例已经超过了当初计划的结束时间？
>
> **用户**：在册大概一百多例吧，具体数得让医助去数。超期多少……没统计过。
>
> **助手**：明白，这两个数现在都拿不到，我先按"说不清"记下来。下一个问题：你们对早矫有明确的结束周期标准吗？比如一个病例计划多久结束、平均延期几个月算正常？
>
> **用户**：一般跟家长说一年半到两年，但没有写下来，也没算过平均延期是几个月。
>
> **助手**：好，记下来了。第三个问题：什么样的孩子该做早矫、什么样的不该做、每次复诊要做什么、做到什么程度算结束——这些有没有写成文字？谁定的？谁最终拍板？

注意：助手每条消息都只在问**一道题**（A1 的两个数、A2 的周期标准、A3 的标准归属），问完就停下等回答，也不预告下一题。这就是"一题一问"——它不会一次给你一张表让你填。

想看完整的一次运行（24 题判分账目、红线降级、动作优先序与报告全文），见 [`docs/example-run.md`](docs/example-run.md)。

## 诊断模型速览

### 四个维度（各 6 题，满分 18）

| 维度 | 管什么 |
|---|---|
| **A · 标准与分级** | 病例底数、过程管理标准、难度分级、医生能力分级、承接容量 |
| **B · 方案审核与结案** | 方案审、审核内容、阶段目标、结束复核、终点定义、偏离处理 |
| **C · 记录与过程数据** | 挂号留痕、记录字段、效率指标入报表、重启与延期统计、进度地图、成本归属 |
| **D · 财务与激励** | 预收款确认、提成发放节奏、负债与产能匹配、结束质量挂钩绩效、单例毛利、就诊次单价 |

### 等级 L1–L4

| 等级 | 分数区间 | 名称 | 一句话特征 |
|---|---|---|---|
| L1 | 0–30 | 无标准 | 没有标准、没有计划时长、没有账，全凭医生个人 |
| L2 | 31–55 | 刚起步 | 有零散做法，但不系统、不留痕、不可复算 |
| L3 | 56–80 | 有体系 | 有标准并能执行、数据可查，收尾复核还有缺口 |
| L4 | 81–100 | 能自转 | 标准、审核、留痕、复核、激励、财务全部到位 |

### 四条红线 R1–R4（命中即封顶）

| 红线 | 判据 | 一句话 |
|---|---|---|
| R1 | 在册早矫病例底数看不见（A1 判 0 或 1） | 看不见 |
| R2 | 没有量化周期标准，也拿不出延期数据（A2 判 0/1，且答完 A2 仍给不出可核数字） | 没有靶子 |
| R3 | 结束无书面复核（B4 判 0 或 1——只有口头确认也算命中） | 没人核 |
| R4 | 预收矫正款在收款当月 / 次月一次性发放全额提成（D2 判 0） | 钱先走了 |

命中任意一条，**等级**封顶到 L2；命中两条及以上，封顶 **L1**，并在报告里单列（总分栏仍显示原分）。判定全部锚在具体题号与分档上，访谈当场就能判。完整判据表见 [`SKILL.md`](SKILL.md) 的「红线」一节。

### 六个动作 ACT-1 – ACT-6

| 动作 | 名称 | 覆盖题号 |
|---|---|---|
| ACT-1 | 建标准、分级、看底数 | A1 A2 A3 A4 A5 A6 B1 B2 |
| ACT-2 | 结果要核 | B4 B5 C4 D4 |
| ACT-3 | 阶段目标要跟 | B3 B6 C5 |
| ACT-4 | 每次就诊都留痕 | C1 C2 C3 C6 |
| ACT-5 | 提成按阶段发 | D2 D4 |
| ACT-6 | 财务的账要算明白 | D1 D3 D5 D6 |

报告**只输出你命中的动作**，不会把六个动作全文倒给你；进不进报告由"缺口够不够大"决定（覆盖题号均分 < 2，或其中出现 0 分），**不挂红线的动作也可能进**。顺序是**档位优先**：`P0`（挂红线的动作里两周内能落地的：ACT-1、ACT-2）→ `P1`（其余挂红线的动作：ACT-5、ACT-6）→ `P2`（不挂红线的：ACT-3、ACT-4），同档按缺口大小排。档位表与排序规则见 [`SKILL.md`](SKILL.md) 的「动作优先序」，落地步骤见 [`reference/playbook.md`](reference/playbook.md)。

### 八个关键指标 K1–K8

| 指标 | 是什么 | 主要来自 |
|---|---|---|
| K1 | 在册早矫病例数 | A1 |
| K2 | 超计划时长（延期）病例占比 | A1 B5 |
| K3 | 计划结束时长（月）与实际结束时长（月） | A2 |
| K4 | 平均延期月数 | A2 B5 |
| K5 | 计划外复诊率（托槽脱落、钢丝扎嘴等） | C2 C3 |
| K6 | 平均椅位占用时长、每例就诊次数 | C3 |
| K7 | 重启率 / 二次治疗率 | C4 |
| K8 | 单例就诊次单价（收入 ÷ 就诊次数） | D6（分母来自 C3） |

**未知即结论**：任何一个指标你答不出来，报告不会估一个数糊过去，而是写"未知"并告诉你哪张报表、哪个字段能查出来。指标不是为了好看，是为了让"拖得越久越不赚钱"从感觉变成算式。

## 可选：用一张 CSV 自查数据

如果机构能导出一张脱敏病例表，`tools/early_ortho_metrics.py` 可以离线帮你把 K1、K2、K3、K4、K6、K7、K8 里能算的部分先算出来（纯 Python 标准库，不联网、不上传）。

```bash
python tools/early_ortho_metrics.py --csv cases.csv \
    --status-active 在治 --status-closed 已结案 --as-of 2026-09-30
```

表头不是上面那套英文列名也没关系，用 `--col-*` 映射：

```bash
python tools/early_ortho_metrics.py --csv 导出.csv \
    --col-case-id 病例号 --col-plan-end-date 计划结束日期 --col-fee 实收金额
```

它最重要的行为是**不肯猜数**：缺列、整列为空、单元格解析不出来，都会打印一行

```
未知（缺少字段: plan_end_date，建议从 方案或病例详情 · 计划结束日期 导出）
```

而不是用 0 顶替。它也不做医疗判断——它只是一张 CSV 的算术汇总。`--help` 里有全部参数，脚本末尾附了一份虚构样例 CSV。

⚠️ 用之前请务必自行脱敏：**不要**把患者姓名、手机号、身份证号导进 CSV，也不要提交进仓库。

## 改这个 skill 的时候

如果你要动题库、评分或建议，先看一眼 [`docs/DESIGN.md`](docs/DESIGN.md) 的「维护约定」。三条最容易踩的：

1. **编号是契约**：四维度、L1–L4、R1–R4、ACT-1–ACT-6、K1–K8 的名称与编号在仓库内唯一。改一处，`SKILL.md`、`reference/`、`docs/`、README 要同步。
2. **判据与题号必须对得上**：每个 ACT 的"什么时候算做到"里用到的题号，必须出现在该 ACT 的覆盖列表里；六个动作的覆盖题号并集必须恰好是 24 题。
3. **改完必须复算样例**：[`docs/example-run.md`](docs/example-run.md) 是自测样例，不是装饰。任何改动都要重算它的维度分、总分、红线结论与优先序，并核对正文每一个数字——样例与规则对不上，等于规则没有被验证过。
